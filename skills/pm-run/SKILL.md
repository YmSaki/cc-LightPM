# LightPM: 実行ループ

メインセッションは調整役になり、実装は1タスクごとに `lightpm:pm-implementer` に渡す。メインのコンテキストにはタスクの要約と報告だけが残る。

最大タスク数: $ARGUMENTS（空なら「待ち」か「完了」になるまで続ける）

## ループ

1. `mcp__lightpm__pm_next` を呼ぶ。
   - 「待ち」なら、理由をそのまま人に報告してループを終える。
   - 「完了」ならプロジェクト完了を報告してループを終える。
   - フェーズが進んだら、そのことを1行で記録する。
2. 結果の「タスク契約」をそのままプロンプトにして、Agent ツールで `subagent_type: "lightpm:pm-implementer"` を起動する。
3. 返ってきた JSON 報告を `mcp__lightpm__pm_complete` に渡す（`taskId`、`status`、`changedFiles`、`acceptance`、`discovered`、`notes`）。
   - **完了**: 次へ。
   - **まだ完了ではない**: 残っている完了条件を添えて、同じタスクを実装者にもう一度依頼する（新しい Agent 呼び出しでよい）。
   - **失敗**: 1回目は次の `pm_next` で同じタスクが再び選ばれるので、そのまま続ける。「2 回続けて失敗」と返ったらループを止めて人に報告する。
4. 報告の `discovered` を1件ずつ、`/lightpm:pm-triage` のルーブリックで分類して `mcp__lightpm__pm_add` で登録する。登録すれば優先度順に回ってくる（今のフェーズで取り組まないものは自動で後回しになる）。
5. 1 に戻る。

## ポイント

- 次のタスクは `pm_next` が決める。気づいた作業は登録しておけば、優先度に応じて順番が来る。
- 人への承認は求めない。判断の理由は監査ログ（`.pm/log/`）と `/pm why <id>` で追える。
- ループを終えるときは、完了したタスク、登録した作業、残り（todo・後回し）を短くまとめる。
- 状態は `.pm/` にあるので、途中で止まっても次のセッションで `/lightpm:pm-run` を呼べば続きから再開できる（作業中のタスクがあれば `pm_next` がそれを返す）。
