# 使い方

## 目的をタスクに分解する

```text
/lightpm:pm-plan TypeScript の CLI ToDo アプリ（追加、一覧、完了）を作る
```

目的を分解し、優先度とやることのチェックリストを付けて登録します。
まず端から端まで通る基本シナリオを1〜3本決め、それを構成するタスクを `max` にします。
残りは[優先度の決め方](rules.md)に沿って優先度を付けます。

## 気づいた作業を登録する

```text
/lightpm:pm-triage ログイン画面で長いメールアドレスが切れる
```

作業中に気づいた問題や新しい依頼を、同じ決め方で分類して登録します。

## タスクを見る

`/pm` は、未完了のタスクを状態ごとに優先度の高い順で表示します。

```text
作業中（1）
- T-0002 [max feature] 保存処理  1/3  前提: T-0001（完了）

未着手（2）
- T-0003 [max feature] add コマンド  0/2  前提: T-0002（作業中）
- T-0004 [high feature] list コマンド  0/1

完了 1 件（/pm list done で表示）
```

`1/3` は、やることの3項目のうち1項目が済んでいることを表します。
前提のタスクがあれば、その状態と一緒に表示します。
前提は表示するだけで、並び順には影響しません。

プロンプトの上の帯には、作業中のタスクと進捗、残数が1行で表示されます。

```text
LightPM · ▶ T-0002 保存処理 [max] 1/3 · 作業中 1 · 未着手 2 · 完了 1  [ 一覧 ]
```

Claude には、毎回のプロンプトに、作業中のタスクと進捗（作業中がなければ最優先の未着手タスク）の要約が600文字以内で渡ります。

## タスク一覧

`/pm view` を実行するか、帯の `[ 一覧 ]` を押すと、タスク一覧のペインが開きます。
行を選んで Enter を押すかクリックすると、そのタスクの説明とやることが展開されます。
完了したタスクは「完了」の行を押すと表示されます。
Esc で閉じます。

```text
LightPM · 作業中 1 · 未着手 2 · 完了 1

作業中（1）
▾ T-0002 [max] 保存処理  1/3
      タスクを JSON ファイルに保存して読み込む
      やること
      [x] 1. 保存できる
      [ ] 2. 読み込める
      [ ] 3. 壊れたファイルでエラーを出す
      種別 feature  前提: T-0001（完了）

未着手（2）
▸ T-0003 [max] add コマンド  0/2
▸ T-0004 [high] list コマンド  0/1

▸ 完了（1）
```

## 進捗を更新する

進捗は、Claude（または実装用のハーネス）が `pm_update` で更新します。

- `check` に項目の番号（1 から）を渡すと、その項目が済みになる
- `uncheck` で済みを戻す
- 状態を指定しなければ、項目を済みにした時点で作業中に、全部済むと完了になる
- `status` で状態を直接変えることもできる（`todo`、`in_progress`、`done`、`dropped`）

取り下げたタスク（`dropped`）は、一覧に出なくなります。

## `/pm` のサブコマンド

| コマンド | 内容 |
| --- | --- |
| `/pm` | 未完了のタスク（作業中と未着手）を優先度順に表示する |
| `/pm view` | タスク一覧のペインを開く |
| `/pm show <id>` | タスクの説明、やること、前提、メモ |
| `/pm list [status\|all]` | 状態を指定した一覧（`todo`、`in_progress`、`done`、`dropped`、`all`） |
| `/pm why <id>` | タスクの変更履歴（優先度や状態をいつ、なぜ変えたか） |
| `/pm init` | `.pm/` を作る（`pm_add` でも自動で作られる） |
| `/pm refresh` | `.pm/` を読み直して帯と一覧を更新する |
| `/pm help` | サブコマンドの一覧 |

## Claude が使うツール

モッドが次のツールを登録します。
Claude からは `mcp__lightpm__pm_list` のような名前で見えます。

| ツール | 内容 |
| --- | --- |
| `pm_list` | どんなタスクがあるかを、状態ごとに優先度順で返す |
| `pm_show` | タスクの説明、やることと進捗、前提、メモを返す |
| `pm_add` | タスクを登録する。`.pm/` がなければ作る |
| `pm_update` | 進捗（`check`、`uncheck`、`status`）や内容を更新する。種別や優先度を変えるときは理由（`reason`）が必須で、変更履歴に残る |

並行して呼ばれても、モッドの中で書き込みを1本の列に並べるので、タスクの ID は重複しません。

## 実装する側とのタスクの受け渡し

LightPM はタスクの管理と表示を受け持ち、実装は行いません。
どのタスクに着手するかを決めたり、実装を進めたりするのは、Claude や実装用のハーネスです。
受け渡しは次の流れになります。

1. `pm_list` でタスクを見て、着手するものを決める（一覧の上ほど優先度が高い）
2. `pm_show` で、そのタスクの説明とやることを読む
3. 着手したら `pm_update` で `status` を `in_progress` にする
4. やることが済むたびに `pm_update` の `check` で済みにする（全部済むと完了になる）
5. 作業中に気づいた別の作業は、`pm_add` で登録する

状態は `.pm/` にあるので、セッションをまたいでも続きから進められます。

## モッドなしで使う

managed settings などでモッドが無効な環境でも、スキルは動きます。
この場合、Claude は `pm_*` ツールの代わりに、[`.pm/` の形式](pm-directory.md)に沿って `.pm/tasks/` を直接編集します。
帯と一覧は表示されません。
