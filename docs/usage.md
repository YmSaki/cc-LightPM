# 使い方

## 目的をタスクに分解する

```text
/lightpm:pm-plan TypeScript の CLI ToDo アプリ（追加、一覧、完了）を作る
```

目的を分解し、分類してタスクとして登録します。
まず端から端まで通る基本シナリオを1〜3本決め、それを構成するタスクを `max` にします。
残りは[優先度の規則](rules.md#優先度)で種別と優先度を決めます。
今のフェーズで取り組まないタスクは、登録した時点で後回しになります。

## タスクを順に実装する

```text
/lightpm:pm-run
```

次のループを回します。

1. `pm_next` が次のタスクを1件選ぶ
2. サブエージェント `pm-implementer` がそのタスクを実装し、JSON で報告する
3. `pm_complete` が完了条件をすべて満たしたかを確かめ、満たしていれば完了にする
4. 報告に含まれる「気づいた別の作業」（`discovered`）を `pm_add` で登録する

ループは「待ち」（着手できるタスクがない）、「完了」（GM の release タスクがすべて終わった）、同じタスクの2回連続の失敗のいずれかで止まります。
`/lightpm:pm-run 3` のように、1回に進める件数の上限も指定できます。
状態は `.pm/` にあるので、止まった後も次のセッションで続きから再開できます。

## 気づいた作業を登録する

```text
/lightpm:pm-triage ログイン画面で長いメールアドレスが切れる
```

作業中に気づいた問題や新しい依頼を、ルーブリックで分類して登録します。
着手する順番は、ほかのタスクと同じ規則で決まります。

## 状態を見る

プロンプトの上の帯に、フェーズ、作業中のタスク、残数が1行で表示されます。

```text
LightPM Alpha · ▶ T-0003 CLI エントリと add を実装する [max] · todo 3 · 後回し 1 · 完了 2  [ 一覧 ]
```

Claude には、毎回のプロンプトに、フェーズと今やるタスク、終わったら呼ぶツールの要約が600文字以内で渡ります。

`/pm` は、フェーズ、作業中のタスク、todo と後回しの一覧、次の候補、フェーズを抜ける条件の進み具合を表示します。
`/pm why T-0003` は、そのタスクが選ばれた理由や後回しになった理由を、監査ログから時系列で表示します。

## タスク一覧

`/pm view` を実行するか、帯の `[ 一覧 ]` を押すと、タスク一覧のペインが開きます。
タスクは `pm_next` が選ぶ順に並び、「次にやる順」の1番が次に取りかかるタスクです。
行を選んで Enter を押すかクリックすると、そのタスクでやること（完了条件）が展開されます。
Esc で閉じます。

```text
LightPM Alpha · 完了 2

作業中（1）
▸ T-0003 [max] CLI エントリと add を実装する

次にやる順（2）
▾ 1. T-0002 [low→max] 保存処理を整理する
      やること（完了条件）
      1. JSON の読み書きを store.ts にまとめる
      2. 既存のテストが通る
      種別 refactor · 前提 T-0001
      主なファイル: src/store.ts
▸ 2. T-0004 [high] list コマンド

前提の完了待ち（1）
▸ T-0005 [max] done コマンド

後回し（1）
▸ T-0006 [low] 色の調整
```

`[low→max]` は、元の優先度は `low` だが、`max` のタスクの前提になっているので[実効優先度](rules.md#フェーズごとの着手できる下限)が `max` になっている、という意味です。

## `/pm` のサブコマンド

| コマンド | 内容 |
| --- | --- |
| `/pm`、`/pm status` | フェーズ、作業中のタスク、todo と後回しの一覧、次の候補、フェーズを抜ける条件 |
| `/pm view` | タスク一覧のペインを開く |
| `/pm init [phase]` | `.pm/` を作る（`pm_add` でも自動で作られる） |
| `/pm next` | 次に選ばれるタスクを表示する（状態は変えない） |
| `/pm list [status]` | タスクの一覧 |
| `/pm why <id>` | 選択、後回し、再分類の履歴 |
| `/pm phase` | 現在のフェーズを表示する |
| `/pm phase set <phase> [理由]` | フェーズを手動で変える（監査ログに `phase.set` として残る） |
| `/pm policy` | 現在のフェーズポリシーの表 |
| `/pm metrics` | 効果の指標を監査ログから集計する (未) |
| `/pm refresh` | `.pm/` を読み直して帯と一覧を更新する |
| `/pm help` | サブコマンドの一覧 |

## 効果を測る (未)

`/pm metrics` は、監査ログから次の指標を集計します。

| 指標 | 定義 |
| --- | --- |
| 優先度の逆転数 | 完了したタスクのうち、選んだ時点でより高い実効優先度の着手可能タスクが残っていた回数 |
| `max` の完了までの時間 | プロジェクトの開始から、`max` のタスクがすべて完了するまでのターン数と経過時間 |

## Claude が使うツール

モッドが次のツールを登録します。
Claude からは `mcp__lightpm__pm_next` のような名前で見えます。

| ツール | 内容 |
| --- | --- |
| `pm_status` | 状態を返す（状態は変えない） |
| `pm_next` | 次のタスクを1件選んで作業中にし、実装者に渡すタスク契約を返す。作業中のタスクがあればそれを返す |
| `pm_add` | タスクを登録する。今のフェーズで着手できないものは後回しになる。`.pm/` がなければ作る |
| `pm_update` | タスクを更新、再分類する。理由が必須で、旧値と新値が監査ログに残る。`todo` への差し戻しと `dropped`（取り下げ）もここで行う |
| `pm_complete` | 実装者の報告を受け取る。完了条件をすべて満たしていれば完了にし、`failed` なら todo に戻す |

並行して呼ばれても、モッドの中で書き込みを1本の列に並べるので、タスクの ID は重複しません。

## モッドなしで使う

managed settings などでモッドが無効な環境でも、スキルとサブエージェントは動きます。
この場合、Claude は `pm_*` ツールの代わりに、[`.pm/` の形式](pm-directory.md)に沿って `.pm/tasks/` を直接編集します。
帯と一覧は表示されません。

選択の規則は Node から呼べる入口を通して適用するので、モッドがなくても同じタスクが選ばれます (未)。
